# Патч коннектора MConnect (VPS): пустой Rights и умеренный темп

Файл патча: `docs/mconnect-connector-patch.diff` (unified diff, `-p1`). Сделан по коду из
`mconnect-connector-vps.tgz` (server.js 107 строк, mconnect.js 214 строк). **На VPS патч не применялся** —
применять вручную по шагам ниже. Секретов в патче нет.

## Что меняется

1. **`mconnect.js → parseBody`**: признаки `HasInterdictions / HasNotations / HasOtherRights` теперь
   `true` / `false` / **`null`** (элемента нет или значение нераспознано). Раньше отсутствующий элемент
   превращался в `false`, и приложение могло показать «Nu există» там, где данных нет.
   В ответ добавлено поле `RightsPresent` (есть ли элемент `Rights` вообще).
   Пустой `Rights` по-прежнему отдаётся как `Rights: []` (по AGE: «нет данных о правах», не «нет обременений»).
2. **`server.js`**: ограничитель — не более **2 одновременных запросов к AGE** (`MC_MAX_PARALLEL`, по умолчанию 2),
   остальные ждут в очереди. Других лимитов нет. Mock-режим ограничителем не затрагивается.
   Mock-ответ получил `RightsPresent: true`.
3. **`test/parse-body.test.js`** (новый файл): 5 тестов разбора `Rights` без сети и без сертификатов.

Совместимость с приложением: приложение понимает и старый (`false`), и новый (`null`) формат — порядок выката
любой. До выката патча различить «false» и «элемента нет» невозможно, поэтому «Nu există» защищает только
новый коннектор.

## Применение на VPS (под тем пользователем, от которого работает сервис)

```bash
# 0. Бэкап и проверка, что на VPS те же исходники, что в архиве
cd <каталог коннектора>            # где лежат server.js и mconnect.js
cp -a . ../mconnect-connector.bak-$(date +%Y%m%d)
wc -l server.js mconnect.js         # ожидается 107 и 214

# 1. Положить патч на VPS (scp) и проверить без изменений
patch -p1 --dry-run < mconnect-connector-patch.diff

# 2. Применить
patch -p1 < mconnect-connector-patch.diff

# 3. Тесты разбора (нужны установленные зависимости: npm ci)
node --test test/

# 4. Перезапуск сервиса (имя юнита/процесса — как у вас: systemd / pm2)
sudo systemctl restart <имя-сервиса>      # или: pm2 restart <имя>

# 5. Проверка
curl -s http://127.0.0.1:8080/health
```

Если `patch --dry-run` выдаёт ошибки (на VPS файлы отличаются от архива) — не применять, прислать `diff`
между VPS-файлами и архивом.

## Проверка после выката

- В mock-режиме: `POST /get-real-estate` отдаёт `"RightsPresent": true`.
- В live: запрос по номеру с известными правами → признаки `true/false`; по номеру без данных о правах →
  `Rights: []` (или `null` в признаках), в приложении — блок «Nu există date privind drepturile patrimoniale…».
- Журнал `logs/requests.log`: формат строк не менялся (`… | cad=… | status=… | note=live ms=… rid=…`).
  `rid` повторов приложения — `<uuid>`, `<uuid>-2`, `<uuid>-3`: одна проверка читается как одна цепочка.

## Откат

```bash
cp -a ../mconnect-connector.bak-<дата>/server.js ../mconnect-connector.bak-<дата>/mconnect.js .
# и перезапуск сервиса
```

## Примечания

- Время ожидания в очереди входит в таймаут приложения (`CONNECTOR_TIMEOUT_MS`, 10 с по умолчанию), а
  `MC_TIMEOUT` (8 с) отсчитывается только после выхода из очереди. При пике нагрузки запрос в очереди может
  получить `TIMEOUT` на стороне приложения — тогда приложение повторит его (паузы 1 с и 3 с).
- Каждая повторная попытка приложения — отдельный запрос к AGE.
- Повторов самого коннектора нет и не добавлялось: повторы делает приложение (только TIMEOUT / UNREACHABLE /
  5xx без кода), чтобы бюджет времени считался в одном месте.
- `package.json` перечисляет только `express` и `xml-crypto`; `@xmldom/xmldom` и `xpath` приходят
  транзитивно через `xml-crypto` (проверено `npm ci`). Лучше добавить их в `dependencies` явно — в патч не
  включено, чтобы не менять `package-lock.json`.
